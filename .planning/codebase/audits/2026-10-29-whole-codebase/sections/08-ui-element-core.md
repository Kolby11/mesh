## Process tree

Bindings evaluate to JSON values and update element attributes. Incremental rendering propagates changed attributes to retained trees and component runtimes; style, layout and semantic projections consume those trees. Fresh rendering reconstructs the values from source.

## Performance findings

Sparse layout builds a path trie for dirty nodes and retains root-to-node paths (`crates/core/ui/elements/src/layout/sparse.rs:69`). Deep trees may incur depth-dependent allocation and insertion costs. This is an unmeasured hypothesis overlapping existing section 08 performance work. Benchmark deep and wide trees with sparse and dense changes, allocations, projection memory and layout-write visits, while checking full-layout parity. Dense changes already have a full-traversal fallback.

Shape hit testing parses points into a vector and allocates transformed vertices (`shape.rs:47`, `:166`; `interaction/src/lib.rs:128`). Measure pointer motion over 1/100/1,000 overlapping shapes with 4/32/256 vertices, allocations and p50/p95 hit-test and frame latency; preserve paint/hit parity and invalidate cached inputs on point, layout and stroke changes. This is an unmeasured hypothesis related to existing hit-test work.

Structural reconciliation rebuilds child lists (`layout/retained.rs:199`), while reparenting removes a child by retaining the old sibling list (`layout/producer.rs:96`). Moving many keyed children between parents may produce quadratic sibling work. Measure 16/1,024/10,000 children in both traversal orders, retain visits, allocations and structural rebuild latency with fresh/retained geometry parity. This is unmeasured and overlaps existing section 08 performance work.

Full semantic capture scans descendant spans to recover direct-child text (`frame.rs:1208`), which can rescan deep chains. Measure chains of depth 16/128/512 and balanced trees of 1,000/10,000 nodes, visits, allocations and p50/p95 capture latency; preserve semantic labels, relationships and diff parity. This is unmeasured and overlaps existing semantic traversal work.

Semantic normalization iterates string and typed attribute views together (`accessibility.rs:506`), materializing string representations of unrelated typed values. Measure full and dirty normalization of 100/1,000 nodes with newly replaced unrelated arrays of 16/128 values, serialization bytes, allocations and frame latency; `OnceLock` limits repeated cost. Preserve semantic parity. This overlaps existing semantic performance work and is unmeasured.

Some background images are resolved and parsed for validation and then again for application (`style/resolve/declaration.rs:463`, `:983`); typed literals may take an earlier path. Measure 1/100/1,000 gradient nodes with 2/8/32 stops and literal or variable inputs, parsing calls, allocations and frame latency, preserving diagnostics, cascade and pixels. This is an unmeasured style hypothesis.

Interaction traversal clones inherited clip stacks (`interaction/src/lib.rs:146`, `interaction_contract.rs:243`). Benchmark pointer and focus walks across 100/1,000/10,000 nodes with 0/1/4/16 nested clips, including transforms and rounded clips, allocations and latency; require targeting and clipping parity. This is an unmeasured cross-section hypothesis related to existing hit-test work; the rejected Skia replay inline-stack experiment is a different path.

## Dead code and redundancy

No new dead code was confirmed in the targeted pass. Legacy handler decoding remains used in frontend rendering, and the elements LRU remains used by layout, style and rendering. Neither is established as removable.

Slider part names are duplicated between `ControlPart::name` and `control_part_names` (`control_parts.rs:35`, `:49`), consumed by matching and compiler validation respectively. Current names agree; derive both from common metadata and test generated-versus-advertised parts if this in-flight API stabilizes. This is a maintenance risk, not observed misbehavior.

Slider pointer-to-value calculation is duplicated for press and drag (`shell/component/input/widgets.rs:214`, `:260`), and range parsing is independently implemented for part geometry (`elements/src/control_parts.rs:92`). The geometry path filters non-finite inputs while the input paths do not. Consider a shared renderer-neutral validated range and fraction contract; test horizontal and vertical press, drag, invalid bounds and endpoint parity. This is related to the non-finite-value candidate below.

Typed and direct-JSON element snapshots independently project similar geometry and state fields (`element/snapshot.rs:99`, `:185`). Existing tests compare their shapes. A shared borrowed projection or generated field list could reduce drift, but retain the direct JSON path unless newly measured: the performance log records why it replaced serialization. Test optional and non-finite fields and repeat the original workload before changing that boundary.

## Logic and core mechanics

The previous report flagged typed attribute equality as a candidate. `StoredAttributeValue::eq` and `AttributeMap::matches_value` compare rendered strings (`crates/core/ui/elements/src/attributes.rs:167`, `:252`), and incremental binding updates skip matching values (`crates/core/frontend/compiler/src/render/mod.rs:1417`). A standalone Rust reproduction using the actual element crate inserted JSON number `1` and then assigned string `"1"`: `matches_value` returned true, `set_value` returned an empty change class, and the retained JSON value remained number `1`. Component runtime props preserve JSON types (`crates/core/shell/src/shell/component/composition.rs:593`). The October 22 performance log explicitly records equal legacy text forms as intentional no-ops, so a change requires component-level evidence and compatibility/performance parity, not an assumption that this is an accidental regression. Compare incremental and fresh rendering for scalar and structured/string collisions before adding a backlog item.

**S08-LOGIC-06 — Authored slider children prevent part styling.** The compiler validates children recursively without a slider-specific prohibition (`crates/core/frontend/compiler/src/compile.rs:891`) and appends generated control parts after authored children (`crates/core/frontend/compiler/src/render/mod.rs:1125`). The part restyle path returns unless the first child is a part (`crates/core/ui/elements/src/style/resolve/subtree.rs:659`), while ordinary traversal skips part nodes (`:138`). A scratch reproduction through the actual restyler gave the track height `6px` without an authored child and `auto` with one before the generated parts. This violates the shipped slider parts contract in `docs/spec/04-styling.md:540`. Make discovery independent of child order, or explicitly validate a no-children contract if that is intended. Test compiled sliders with authored and conditional children through initial and retained restyles. Confirmed at the restyler boundary; compiled-component reproduction remains needed.

**S08-LOGIC-10 — Reference expansion changes quoted asset filenames.** Reference expansion scans raw `var(` and `prop(` text without tracking quotes (`style/resolve/value.rs:399`), and quoted relative background URLs are accepted (`style/parse.rs:804`). A scratch reproduction through the actual style resolver lowered `url("assets/var(--missing).png")` to `assets/.png` with no diagnostic. Preserve quoted contents during expansion and test real asset loading, escapes, quoted commas and parentheses. Confirmed at the resolver boundary; end-to-end asset loading remains untested. This strengthens the earlier report's candidate and differs from the existing backlog item about absolute paths.

**S08-LOGIC-11 — Non-finite accessibility values invalidate frame snapshots.** Element validation accepts `aria-valuemin="NaN"`, accessibility projection parses it (`accessibility.rs:688`), and frame validation rejects non-finite values (`frame.rs:1290`); shell snapshot handling then clears the last snapshot and logs (`shell/component/rendering/mod.rs:1449`). A scratch reproduction through the actual element APIs returned no validation diagnostic and `NonFiniteAccessibilityValue` from frame capture for a slider with that attribute. Reject or sanitize non-finite values with a local diagnostic; test dynamic values, frame publication and recovery through a compiled component. Confirmed at the element/frame boundary; downstream event effects remain untested. This strengthens the earlier report's candidate.

**S08-LOGIC-08 — Adding a key can invalidate retained layout.** Previously unkeyed Taffy IDs are marked obsolete (`layout/retained.rs:83`), but reconciliation reuses a mapped ID if the new node has a key (`:173`), without checking whether the prior node was stable. `WidgetNode::set_mesh_key` preserves `NodeId`, so the reused ID is then removed as obsolete. A scratch binary using the public layout API reproduced a panic at `layout/lowering.rs:587`: it laid out a row with an unkeyed child, assigned that child a key and changed its width, then requested structural layout. Guard reuse with prior stable identity and test root and child transitions, keyed reordering and fresh-layout parity. Confirmed for the public API; production shell reachability remains unverified. Existing tests cover other identity transitions.

`flex-direction: column-reverse` is lowered to `Column`, and `row-reverse` falls through to `Row`, both in literal and resolved declarations (`style/resolve/literal.rs:107`, `style/resolve/declaration.rs:1170`). The representation has no reverse variants. This silently loses reversal; the detailed spec does not establish that reverse values are supported, so the contract question is whether to implement or diagnose them. Test literal and variable-based declarations through layout and diagnostics before classifying it as a shipped contract defect.

**S08-LOGIC-07 — Axis-specific gaps share one value.** The CSS coverage guide lists `row-gap` and `column-gap` as implemented, but both declarations write the same `ComputedStyle.gap` (`style/resolve/literal.rs:57`; `style/resolve/declaration.rs:897`), which is applied to both Taffy axes (`layout/lowering.rs:240`). A scratch reproduction through the actual resolver gave a single gap of 20 for `row-gap: 4px; column-gap: 20px`, without a diagnostic. Represent and lower the axes separately, preserving `gap` shorthand and cascade semantics. Test wrapped flex with unequal gaps, literals and variables, in fresh and retained layout. Confirmed at the resolver boundary; a layout regression has not yet run. The existing transition-shorthand backlog item is related but does not cover axis geometry.

**S08-LOGIC-12 — Several text properties do not inherit.** The inherited-property mask and both compiler and retained inheritance paths cover color, family, size, weight and line height, but omit font style, letter spacing, alignment and text direction (`style/types.rs:20`, `frontend/compiler/src/style.rs:157`, `style/resolve/matching.rs:102`). In a scratch retained restyle, a parent with `font-style: italic; direction: rtl` computed italic/RTL while its text child computed normal/LTR. The styling spec states inherited text values preserve parent inheritance. Extend inherited masks and propagation as appropriate to the supported profile; test initial and retained child rendering, explicit overrides and control parts. Confirmed at the retained-style boundary; compiled rendering and the precise property scope still need regression coverage.

The element contract validator's profiles omit runtime-supported slider `orient` and several popover attributes (`element/contracts.rs:546`, `:561`; `element/validate.rs:16`). A repository search found no production caller of this validator, so this is API/schema drift rather than an established editor diagnostic. The LSP maintains its own popover attribute list; older audit work already covers the broader duplication. If the validator remains public, add table-driven parity against the documented attributes and runtime consumers.

**S08-LOGIC-09 — Invalid shape geometry retains a rectangular hit region.** Invalid geometry yields no shape paint content (`frontend/render/src/display_list/paint_node.rs:207`), but hit testing falls back to the rectangular box when geometry is absent (`interaction/src/lib.rs:128`). A scratch binary using the actual element and interaction crates constructed a 100-by-100 polygon with `points="bad"`: `ShapeGeometry::from_node` returned `None`, while `pointer_hit_test` at its center returned the shape. The [element guide](../../../../../docs/frontend/elements.md) says shape boxes paint no background or border and hits land on the painted shape. Return no shape hit for invalid geometry, with compiled-component and event-delivery regressions, including malformed and unsupported attributes. Confirmed at the element/interaction API boundary; full event delivery remains untested.

Element snapshots derive the type and exposed fields from the lowered runtime tag (`element/snapshot.rs:116`, `:324`), while some authored elements lower to another tag, such as `command-item` to `row` (`element/contracts.rs:555`). Check the author-facing introspection contract and exercise a compiled element before deciding whether returning the lowered type is incorrect. Existing tests use direct tags.

Negative `scale()` values parse into the computed transform (`style/parse.rs:88`), but shared transform construction clamps them to zero (`interaction_contract.rs:558`, `:651`). This collapses instead of reflecting. The documented subset does not explicitly specify negative scales, so confirm the intended profile and test actual parsed paint and hit geometry, zero scales and transform origins before classifying the impact; diagnose negative values if they are intentionally unsupported.

Border parsing recognizes hex colors but silently returns transparent for other color syntax (`style/parse.rs:162`). A resolver reproduction showed `color: red` as opaque red but `border-color: red`, `border-color: rgb(255,0,0)` and `border: 1px solid red` as transparent without diagnostics. The CSS coverage guide says border colors are implemented but does not define their accepted color formats; clarify the supported profile, then support consistent CSS color parsing or diagnose unsupported formats. Test literals, token-expanded functional colors, shorthand/longhand and rendered pixels. Confirmed at the resolver boundary; contract scope remains to be decided.

**S08-LOGIC-13 — Cached rule indexes miss in-place edits.** `StyleRuleIndex::is_for` compares only a slice pointer and length (`style/resolve/index.rs:176`), while the index retains compiled declarations. A scratch public-API reproduction changed a same-length rule vector in place from `width: 4px` to `20px`: `restyle_subtree_cached` retained 4px, while a fresh index produced 20px. Use an explicit rule revision or an enforced immutable ownership contract; test declaration and selector edits, allocation reuse and cached-versus-fresh parity. Confirmed at the public API boundary; production reload reachability remains unverified. This strengthens a candidate in the previous section report.

**S08-LOGIC-14 — Hidden popovers leave trigger expansion stale.** The accessibility contract says a popover trigger is expanded exactly while its popup is open (`docs/spec/09-accessibility.md:54`). Hidden nodes are omitted from semantic publication before `project_popover_expansion` derives trigger state (`accessibility.rs:887`), so a closed, hidden popup contributes no false value. A scratch `AccessibilityTree::publish` reproduction with a trigger authored `aria-expanded="true"` and a hidden, closed anchored popover returned `Some(true)` for the trigger. Derive disclosure state from retained relationships independently of semantic exposure; test open and closed, hidden and promoted, conflicting authored state, multiple popovers and full/dirty publication. Confirmed at the accessibility API boundary; production promoted-popup reachability needs an integration regression.
