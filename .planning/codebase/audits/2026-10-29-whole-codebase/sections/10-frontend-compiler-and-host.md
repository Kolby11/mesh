# Section 10 — Frontend compiler and host

## Scope and coverage

Review in progress. The prior inventory assigns 139 files and the continuation inventory identifies additional files; the working tree also contains an in-flight frontend-runtime extraction. The observations below are interim and do not establish complete file, test or caller coverage.

## Process tree

Module graph and source paths feed compilation, import resolution and contract validation. The catalog publishes compiled roots and dependency data. A host resolves component instances and their state, evaluates template expressions through the runtime, constructs or patches element trees, and passes effects and dirty state to shell orchestration. Reload and recovery must preserve consistent generations and usable prior state.

## Performance findings

Local component lookup scans the alias-keyed map and clones the resolved component (`frontend/compiler/src/lib.rs:491`); host resolution calls it before component memo handling (`shell/component/composition.rs:180`). This is an unmeasured hypothesis related to existing S10 import work. Benchmark 1/100/1,000 bindings and 10/100/1,000 repeated instances, cold builds, warm memo hits and leaf updates; record map visits, cloned AST bytes, allocations and frame p50/p95. Preserve owner scoping, ambiguity detection and contribution parity.

Catalog creation separately rereads watched files for its source fingerprint and compiled revision (`frontend/runtime/src/catalog.rs:319`, `frontend/compiler/src/lib.rs:435`). Shared sources can multiply I/O. Measure 10/100/1,000 roots with shared versus disjoint imports and cold edits versus graph-only activation, read counts/bytes, memory and activation latency. A single transaction snapshot could reduce duplication if it preserves contained reads and concurrent-edit detection. This is unmeasured and overlaps catalog refresh work; the independent correctness race is described below.

Template evaluation repeatedly calls the process-global expression cache and clones captured locals (`frontend/compiler/src/render/expr_eval.rs:19`, `frontend/compiler/src/lib.rs:79`); two-way binding lowering also clones element ASTs during render (`frontend/compiler/src/render/mod.rs:920`, `bindings.rs:4`). Measure release keyed lists and bound controls at 100/1,000/10,000 rows or controls, varying bindings, item size and fresh versus one-item patches. Track cache-lock visits, cloned bytes, allocations and frame latency; preserve Luau scope, dynamic key and event parity. These are unmeasured and overlap existing binding work.

`NodeServiceFieldDependencies::build` constructs a forward index alongside its reverse index (`frontend/runtime/src/service_deps.rs:18`), while its forward accessor is test-only and production callers use reverse lookup. Verify external and future API intent, then measure 100/1,000/10,000 nodes with 0/1/8 fields, allocations and structural rebuild latency before changing it. This overlaps service-observation backlog work.

Slot composition constructs contributions before applying the host's maximum (`frontend/compiler/src/render/mod.rs:397`, `:716`; `shell/component/composition.rs:406`). Graph resolution retains matching contributions beyond that limit. Measure 1/10/100 contributions at maximum 1/4/unlimited, cold and repeat mount, initialized components, allocations and latency; preserve ordering, placement, diagnostics and lifecycle semantics. This is an unmeasured hypothesis; whether discarded instances can produce observable side effects requires a separate integration test.

The parsed-component cache clones full ASTs while holding a process-wide mutex (`frontend/compiler/src/compile.rs:438`), while catalog compilation uses Rayon (`frontend/runtime/src/catalog.rs:858`). Measure 10/100/1,000 modules with shared versus distinct sources, cold and warm cache, and 1/2/4/8 workers; record lock hold/wait, clone bytes and activation latency. Preserve cache bounds and the path-correct asset resolution described below. This is unmeasured and overlaps existing S10 import work.

## Dead code and redundancy

Compiler accessibility projection and element normalization separately extract overlapping role, label, state and numeric attributes (`frontend/compiler/src/render/elements.rs:480`; `ui/elements/src/accessibility.rs:500`). Their baseline and live-tree responsibilities differ. Consider sharing only extraction/coercion with initial/patch and full/dirty parity for precedence, typed values, labels, hidden nodes and authored baselines; measure cold typed attributes before changing it.

JSON value hashing is implemented in frontend runtime and shell fingerprint paths with different numeric subtype encoding (`frontend/runtime/src/fingerprint.rs:20`, `shell/component/runtime_tree/fingerprint.rs:380`, `shell/component/interaction_state.rs:888`). A scratch reproduction confirmed that unequal JSON values `4607182418800017408` and `1.0` produce the same slot-prop fingerprint because their integer bytes and float bits are identical. Slot memoization compares that fingerprint (`shell/component/memo.rs:171`); callback argument hashing also uses the helper. Add numeric subtype tags and assess whether memo equality must compare authoritative inputs rather than only a hash. Confirm actual invalidation and dynamic-prop reachability before claiming a user-visible stale subtree; test typed scalars, arrays/objects, slot props and interaction-cache parity.

`RuntimeGenerationIndex::register` and `sync` duplicate insertion and generation-bump logic (`frontend/runtime/src/generation.rs:64`); both have production callers, so neither is dead. A shared update function can retain both semantic APIs. Test registration order, repeated sync, child-before-parent registration and subtree revisions. Public adapter methods, `UiTag` variants and fixture compatibility paths without identified production callers remain API-review candidates, not confirmed dead code.

The adapter unit test `adapter_rejects_effects_without_their_capability_scope` expects a service effect to be rejected (`frontend/shell-adapter/src/lib.rs:1235`), while the ABI deliberately defers service authorization to contract-aware dispatch (`frontend/abi/src/lib.rs:97`). Update the stale assertion and test deferred authorization through real dispatch; do not reintroduce an unconditional control gate. This contradiction is source-confirmed; the focused test was stopped during compilation to preserve disk space and has not been run.

## Logic and core mechanics

**S10-LOGIC-01 — Production preview expressions have no evaluator.** `build_preview_tree_with_state` supplies no composition (`frontend/compiler/src/lib.rs:648`), and expression evaluation without one returns null in non-test builds (`render/expr_eval.rs:30`). Under `cfg(test)` the same path uses real Luau, so unit tests do not exercise production behavior. A scratch binary compiled `<text>{name}</text>` with a store returning `Alice`; the production preview returned empty text. The scripting `LocaleBoundState` documentation explicitly recommends the preview API for translations (`runtime/scripting/src/context/state.rs:559`). Supply a real evaluator or require one explicitly, and add non-unit integration coverage for text, attributes, conditionals, loops and localization. Confirmed at the public API boundary; actual external consumers remain unknown. This is related to the older expression-semantics audit, not a claim that its removed handwritten evaluator remains.

**S10-LOGIC-02 — Later successful expressions resolve an active failure diagnostic.** A failed template expression records an active issue and marks the frame failed (`shell/component/diagnostics.rs:93`), but each subsequent successful expression resolves the same instance issue (`shell/component/composition.rs:122`). Frame finalization still retains the old tree or displays the failure placeholder (`shell/component/rendering/mod.rs:516`), so the failure can remain present without an active diagnostic. Resolve only after the complete expression transaction succeeds; test failing then successful expressions in one instance, failed-frame retention and later recovery. High confidence from source; runtime regression not yet run.

**S10-LOGIC-03 — Contribution reuse omits the manifest revision.** Primary catalog reuse compares the manifest fingerprint (`frontend/runtime/src/catalog.rs:859`), but contribution reuse checks only source path and source fingerprint (`:943`). A manifest-only change can therefore retain a contribution's old `compiled.manifest` while its primary entry changes. Include the manifest identity in contribution reuse and test changed dependencies, metadata and settings with unchanged source. High confidence from source; an end-to-end regression remains needed. Runtime grants are obtained from activation-resolved capabilities, so this evidence does not establish a permission escalation.

**S10-LOGIC-04 — Source fingerprints can describe bytes that were not compiled.** The compiler parses a source read (`frontend/compiler/src/compile.rs:383`), while catalog fingerprinting and compiled revision construction reread watched paths afterward (`frontend/runtime/src/catalog.rs:319`, `frontend/compiler/src/lib.rs:435`). If a file changes between these operations, the old AST can be identified by the new bytes; a later graph rebuild can reuse it. Reload also records watched mtimes after compilation (`shell/runtime/reload.rs:32`), potentially acknowledging the new version without compiling it. Derive fingerprints from exact parsed bytes or validate a coherent pre/post snapshot and retry; test edits during compilation, watcher recovery and last-known-good publication. High confidence from source; a controlled scheduling regression remains needed.

**S10-LOGIC-05 — Parsed component cache retains another file's asset base.** The cache is keyed by source text, but a miss absolutizes relative URLs against the source file's directory before inserting the parsed component (`frontend/compiler/src/compile.rs:383`). A scratch reproduction compiled identical source from directories `a` and `b`; both compiled declarations pointed to `a/icon.png`. Parallel catalog compilation can make the selected base depend on scheduling. Cache the unbound AST and apply the asset base per file, or include the canonical base in the key. Test identical files in separate modules, local imports, concurrent compilation and reload. Confirmed at the compiler API boundary; downstream resource access and containment effects need separate verification.

**S10-LOGIC-06 — Slot limits are applied after contribution initialization.** The compiler calls `render_slot` and only then truncates the returned children to the host maximum (`frontend/compiler/src/render/mod.rs:397`, `:716`). The shell resolver constructs each selected contribution (`shell/component/composition.rs:497`), and runtime creation invokes `init` and `mount` (`shell/component/runtime.rs:900`, `:951`). Thus contributions beyond the limit can initialize before being dropped from the visible tree. Apply the limit to the selected ordered contributions before building them; test a host with max one and multiple contributions, lifecycle effects, cleanup and both slot forms. High confidence from source; runtime integration and cleanup effects remain unverified.

**S10-LOGIC-07 — Glass bar status retains stale accessible state on service loss.** The unavailable-audio branch changes the text and icon but leaves `volume_label` unchanged, and the unavailable-power branch changes only the text, retaining the previous battery label, icon and low/charging state (`modules/frontend/glass-bar/src/components/status.mesh:67`, `:79`). When a previously available service disappears, the displayed or accessible state can describe its last value as current. Set all dependent presentation fields to a localized unavailable state and test available → unavailable → recovered transitions. Confirmed from the module's control flow; live service transition testing remains needed.

The same component and its workspace strip also hardcode user-facing and accessible English text (`status.mesh:3`, `:42`, `:76`, `:96`; `workspaces.mesh:55`) despite the platform localization requirement and bundled English/Slovak catalogs. Route these labels through translations and test locale switching and accessible names. Source-confirmed; the module has not been comprehensively audited for every string.

The status chip labels its value as input language but derives it once from `mesh.locale.current()` (`status.mesh:3`, `:40`), which is the UI locale rather than keyboard input state. It also does not reactively refresh that assignment. Either label it as the UI language and observe locale changes, or connect a real input-language source; test independent UI locale and keyboard-layout changes. Source-confirmed mismatch; the desired product behavior needs a decision.

**S10-LOGIC-08 — Low battery percentages are multiplied as if fractional.** The power interface defines `level` as a percentage from 0 to 100 (`modules/interfaces/power/module.json:19`), but glass-bar status, its control center, the orbit status strip and battery widget multiply values at or below one by 100 (`glass-bar/src/components/status.mesh:84`, `control-center.mesh:63`, `orbit-bar/src/components/status-strip.mesh:42`, `battery-widget/src/main.mesh:25`). A 1% battery is therefore displayed as 100%, and 0.5% as 50%, masking the low-battery state. Consume the interface's declared units and test 0, 0.5, 1, 2 and 100 percent including icon and low-battery labels. Confirmed from the interface and module source; live integration remains untested.

**S10-LOGIC-09 — Settings can display a false instance override as true.** Advanced settings selects a value with `has_override and override or inherited_value` (`modules/frontend/settings/src/components/advanced-page.mesh:440`, `:522`). In Luau an explicit `false` instance override falls through to an inherited `true`; the displayed toggle and subsequent action use that incorrect value (`:100`, `:540`). Use explicit nil-aware selection and test false against true defaults/global overrides, scope switching, reset and reload. Confirmed from source and language semantics; runtime integration remains untested.

**S10-LOGIC-10 — Wi-Fi details retain a disconnected network.** The Settings Wi-Fi projection sets `active_network` when a connected row appears but does not reset it before processing an enabled network list (`modules/frontend/settings/src/components/wifi-page.mesh:152`). A later empty list or list with no connected row leaves the prior SSID visible. Initialize the value to localized not-connected each projection; test connected → disconnected with empty and nonempty lists, disabled/unavailable and recovery. High confidence from source; live integration remains untested.

**S10-LOGIC-11 — Concurrent catalog reloads can overwrite newer publications.** `FrontendCatalogHandle::reload_module` snapshots a base, compiles outside the lock, then unconditionally publishes and takes a separate snapshot (`frontend/runtime/src/catalog.rs:459`). A concurrent replacement or reload can publish after its base was read and be overwritten by the stale candidate; the returned published snapshot can also belong to another operation. `restore_if_current` protects rollback, not this publication. Compare-and-publish against the base version and return the actual committed state under the same lock; test two controlled concurrent reloads, an intervening graph replacement and rollback. High confidence from public API source; concurrent shell reachability is unverified.

**S10-LOGIC-12 — Catalog rollback reuses version numbers.** `restore_if_current` replaces the current state with the entire previous state, including its earlier version (`frontend/runtime/src/catalog.rs:447`). The public sequence v0 → publish A as v1 → restore v0 → publish B as v1 permits a delayed restore for A expecting v1 to overwrite B. Keep a monotonic generation or unique commit token on rollback and test this ABA sequence alongside publication races. Confirmed from the public API's state transitions; concurrent production reachability remains unverified.

**S10-LOGIC-13 — Settings optimistic values never reconcile.** Advanced Settings stores pending prop, provider and module-enabled values and prefers them over subsequent service snapshots (`modules/frontend/settings/src/components/advanced-page.mesh:165`, `:271`, `:337`, `:351`, `:441`, `:595`). There is no removal or reset of those maps in the component. A rejected operation or later external change can therefore leave the displayed value stuck at an older optimistic value. Reconcile pending writes with authoritative completion/revision and surface failures; test success, rejection, external updates and scope/profile changes. Confirmed from source; command-delivery behavior needs integration testing.

**S10-LOGIC-14 — Device fallback literals become missing translation markers.** `value_or` translates every fallback (`modules/frontend/settings/src/components/device-info-page.mesh:106`), but OS name/version callers supply literal `"Linux"` and `""` (`:164`). Missing values therefore resolve to visible `!!Linux` and `!!` markers rather than those intended fallbacks. Separate literal values from translation keys and test absent or empty OS fields in both bundled locales. Confirmed from source; rendered integration remains untested.

Audio Settings also retains its previous output name and description when its provider becomes unavailable (`audio-page.mesh:115`); device Settings retains its prior hardware details under a partial-state label (`device-info-page.mesh:153`). Clear or explicitly mark stale data, and test available → unavailable → recovered transitions. These are source-confirmed control flows; decide whether partial device data is intentionally retained.

`catalog_changes` identifies existing primary modules only by key presence or an explicit changed-module argument and does not compare node-slot placements (`frontend/runtime/src/catalog.rs:478`). Same-ID revised entries or placement-only changes can be published without including the host in affected modules. Test the public graph-backed replacement and retained surface behavior, including slot order and props, before classifying production impact; profile activation may independently rebuild surfaces.

**S10-LOGIC-15 — Quick Settings sliders expect the wrong change payload.** The volume and brightness handlers index `event.value` (`modules/frontend/quick-settings/src/main.mesh:130`, `:138`), while shell slider change dispatch passes the number itself (`shell/component/input/mod.rs:638`). Indexing that number can fail before the service command runs. Accept the numeric value, with any desired compatibility normalization, and test pointer and keyboard changes through real component dispatch and provider requests. High confidence from source; an end-to-end regression remains needed.

**S10-LOGIC-16 — Implicit text loses explicit inherited-style declarations.** The compiler resolves rules for generated text nodes, then calls `inherit_text_style` with an empty explicit mask (`frontend/compiler/src/render/mod.rs:514`, `:571`), overwriting fields such as color with the parent. A scratch preview of `<box>hello</box>` with green `box` and red `text` rules produced green text. Preserve the matched explicit-property mask and test literal and expression text, explicit `<text>`, parent inheritance and live final restyle. Confirmed at the compiler preview boundary; shell finalization may change the live result.

The debug inspector's module filter similarly forwards input change to a handler that reads `event.value` (`modules/frontend/debug-inspector/src/components/modules-view.mesh:10`, `src/main.mesh:83`, `:569`), while text-input dispatch passes a string (`shell/component/input/widgets.rs:183`). Accept the string value and test actual input, callback forwarding and filter results. High confidence from source; live behavior remains untested.

`RuntimeGenerationIndex::rebuild` resets its revision counter (`frontend/runtime/src/generation.rs:125`), while the revision participates in frontend effect stamps (`shell/component.rs:1720`). Different runtime sets can receive the same revision after rebuild. Test queued stale effects across rebuild and clear, and preserve a monotonic epoch if equality can admit stale work. The index behavior is source-confirmed; stale-effect dispatch reachability remains unverified.

**S10-LOGIC-17 — Language selector can retain an optimistic selection.** The selector holds a pending locale until the observed locale differs from the previous one (`modules/frontend/language-popover/src/main.mesh:200`, `:222`). A rejected or no-op selection can leave it pending indefinitely. If an external change selects a third locale, the pending branch clears its marker without applying that observed locale because reconciliation is in `elseif`. Reconcile authoritative state on completion or failure and when the observed locale differs; test no-op, rejection, external changes and `LocaleChanged` delivery. High confidence from source; runtime integration remains untested.

**S10-LOGIC-18 — Theme selector uses a fixed list instead of the installed catalog.** The current working-tree selector builds its ring from a hardcoded list (`modules/frontend/theme-selector/src/main.mesh:81`, `:158`), although it reads `theme.themes` for coverage (`:233`). Installed themes absent from the list cannot be selected there, while listed but absent themes can remain offered. Build options from the authoritative catalog with appropriate fallback visuals; test installed custom themes, removals, empty catalogs and failed selection. Confirmed from source; live activation remains untested and this file has concurrent work in progress.

The theme widget infers dark mode from whether the theme ID contains `dark` and listens only for theme-ID changes (`modules/frontend/theme-widget/src/main.mesh:26`). Dark themes with other names and mode changes within one theme can show the wrong icon. Observe authoritative theme mode and test same-theme mode changes and arbitrary IDs. Source-confirmed; live update behavior needs a component test.

Theme selection also holds a pending choice until the service reports a different ID from the previously active theme (`theme-selector/src/main.mesh:192`, `:250`). A rejected or no-op request can leave the optimistic selection and event state in place indefinitely. Reconcile against request outcome and authoritative service state; test failed, absent and already-active selections plus external switches. Source-confirmed control flow; live error delivery remains untested.

**S10-LOGIC-19 — Keyboard volume changes leave the audio popover in drag mode.** Every volume change sets `volume_dragging` and only the release handler clears it (`modules/frontend/audio-popover/src/main.mesh:109`). Keyboard slider handling dispatches change without release (`shell/component/input/keyboard.rs:172`), so later backend values are ignored until a pointer release. Distinguish keyboard changes from pointer drag or provide an appropriate completion signal; test keyboard adjustment followed by external update, pointer drag/release and provider failure. High confidence from source; a live regression remains needed.

The profile menu clears its requested profile only when it becomes active (`modules/frontend/profile-menu/src/main.mesh:39`, `:48`, `:68`), so rejected switches or an external switch to another profile can leave a stale pending indicator. Reconcile with completion/failure and newer authoritative state; test both cases. Source-confirmed control flow; service-result integration remains untested.

**S10-LOGIC-20 — Title truncation can split UTF-8.** The window-title widget uses byte length and `string.sub(title, 1, 34)` on application titles (`modules/frontend/window-title-widget/src/main.mesh:5`); glass-bar now-playing similarly slices media titles (`glass-bar/src/components/now-playing.mesh:51`). A multi-byte character crossing either boundary is truncated inside its encoding, and non-ASCII text is shortened prematurely. Use the text element's ellipsis or Unicode-aware truncation; test accented text, combining characters, emoji and CJK. Confirmed from Luau string semantics and source; rendered behavior remains untested.

Glass Widgets weather and media cards also hardcode displayed condition, fallback and idle text (`modules/frontend/glass-widgets/src/components/weather-card.mesh:53`, `media-card.mesh:53`) despite bundled locale catalogs. Move those user-facing strings into the catalogs and test locale changes in available, unavailable and idle states. Source-confirmed; full localization coverage remains open.
