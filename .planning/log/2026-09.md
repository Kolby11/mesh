## 2026-09-02 — Fail activation closed without resolved capabilities

`working tree` · area: activation capability resolution

Frontend runtime creation and backend launch-candidate validation now require
the immutable effective capability map produced by graph/profile activation.
Missing activation grants produce an isolated frontend runtime failure or a
`missing_capability` backend status; raw required and optional manifest
declarations are no longer used as production grants. Direct unit fixtures use
explicit test-only adapters because they do not run through activation.

**Verified.** The focused frontend and backend regressions, the 17-test service
contract group, all 5 capability tests, workspace check, and formatting check
passed. The complete shell library suite ran with 776 passed, 47 failed, and
131 ignored; the failures were in existing unrelated renderer, interaction,
debug, lifecycle, and fixture coverage.

## 2026-09-02 — Make the capability catalog the production authority

`working tree` · area: capability authority

The fail-open `Capability::privilege_level` classifier is deprecated. Mutable
`CapabilitySet` construction is now crate-private; production activation
adapts only immutable `EffectiveCapabilities`, while host-owned requests
validate through the closed `CapabilityCatalog`. Backend launch and runtime
APIs carry the resolved `CapabilitySet` instead of rebuilding grants from raw
ids.

**Verified.** The capability tests (6 passed), backend tests (36 passed),
scripting tests (261 passed, 26 ignored), focused shell sound tests (2 passed),
and focused shell backend capability tests (2 passed) passed. Formatting and
workspace checks passed. The complete shell library suite ran with 777 passed,
46 failed, and 131 ignored; failures remained in existing renderer,
interaction, debug, lifecycle, and fixture coverage.
