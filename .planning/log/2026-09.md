## 2026-09-02 — Fail activation closed without resolved capabilities

`working tree` · area: activation capability resolution

Frontend runtime creation and backend launch-candidate validation now require
the immutable effective capability map produced by graph/profile activation.
Missing activation grants produce an isolated frontend runtime failure or a
`missing_capability` backend status; raw required and optional manifest
declarations are no longer used as production grants. Direct unit fixtures use
explicit test-only adapters because they do not run through activation.

**Verified.** The focused frontend and backend regressions, the 17-test service
contract group, all 5 capability tests, workspace check, and formatting check
passed. The complete shell library suite ran with 776 passed, 47 failed, and
131 ignored; the failures were in existing unrelated renderer, interaction,
debug, lifecycle, and fixture coverage.

## 2026-09-02 — Make the capability catalog the production authority

`working tree` · area: capability authority

The fail-open `Capability::privilege_level` classifier is deprecated. Mutable
`CapabilitySet` construction is now crate-private; production activation
adapts only immutable `EffectiveCapabilities`, while host-owned requests
validate through the closed `CapabilityCatalog`. Backend launch and runtime
APIs carry the resolved `CapabilitySet` instead of rebuilding grants from raw
ids.

**Verified.** The capability tests (6 passed), backend tests (36 passed),
scripting tests (261 passed, 26 ignored), focused shell sound tests (2 passed),
and focused shell backend capability tests (2 passed) passed. Formatting and
workspace checks passed. The complete shell library suite ran with 777 passed,
46 failed, and 131 ignored; failures remained in existing renderer,
interaction, debug, lifecycle, and fixture coverage.

## 2026-09-02 — Remove the unconsumed CapabilityHandle abstraction

`working tree` · area: capability authority

The downstream API review found no protected API or production caller that
accepted `CapabilityHandle`; its only path was the crate-private mutable grant
helper and its unit test. The unused token, mutable grant helper, and mutable
constructor were removed. Runtime authorization continues to use immutable
catalog-resolved `CapabilitySet` values.

**Verified.** The capability tests (5 passed), formatting check, workspace
check, and compilation of all workspace test targets passed.

## 2026-09-03 — Stabilize debug snapshot collection ordering

`Shell::debug_snapshot` now sorts module entries by stable module ID and
visible active surfaces by stable surface ID before the DTO is serialized.
Applying the ordering at the snapshot boundary keeps hash-map insertion order
from changing debug telemetry or downstream cache/diff payloads.

**Verified.** The insertion-order serialization regression passed. The full
`mesh-core-shell --lib` suite ran with 781 passed, 46 failed, and 132 ignored;
its failures remain in unrelated rendering, interaction, debug, fixture,
lifecycle, and profiling coverage. `cargo fmt --all -- --check`,
`git diff --check`, and `nix develop -c cargo check --workspace` passed.

## 2026-09-03 — Bound diagnostic history and debug export

Per module instance, diagnostic history now retains at most 256 records with
bounded issue-code, message, and source-path storage. Generated health
summaries are capped at 8 KiB, and the debug diagnostic projection is capped at
64 KiB per instance. Truncation and dropped records share the deterministic
`diagnostics:overflow` warning so the bound remains observable.

**Verified.** The diagnostics suite passed with 10 tests and 1 ignored; the
focused shell debug payload bound test passed. The full `mesh-core-shell --lib`
suite ran with 781 passed, 47 failed, and 132 ignored; its failures remain in
unrelated rendering, interaction, lifecycle, fixture, and profiling coverage.
`cargo fmt --all -- --check`, `git diff --check`, and
`nix develop -c cargo check --workspace` passed. An initial bound test exposed
that the health-status prefix was not included in the byte budget; the limit
was corrected before the passing run.
