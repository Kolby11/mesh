# August 2026

## 2026-08-02 — Popups and overlays verified complete

`working tree` · area: popovers and component runtime

The stale popup/overlay umbrella item is closed. In-tree `<popover>` content is
already promoted to transient `xdg_popup` child surfaces with custom content,
content sizing, anchoring, pointer and keyboard routing, hover-bridge dismissal,
one-open-per-trigger exclusivity, and compositor-dismiss synchronization. The
remaining automatic-overflow and legacy-popover migration work stays tracked as
separate backlog items.

The completion audit exposed two composition regressions and removed an
intentional debug-dump test that had been left in the suite. Handler props now
preserve arguments bound by the child (for example `onselect(item.id)`) after
resolving the parent's callback, and Luau template-expression invalidation now
accumulates changed public members across multiple synchronizations until the
template evaluation boundary. The language popover consequently dispatches its
selected locale and repaints the trigger flag immediately; its event payload is
also the primary source for that flag.

The focused scripting cache regression passes, and the shell popover suite
passes with 41 tests plus one ignored release-only benchmark.

## 2026-08-02 — Widget-tree paint uses the display-list command builder

`working tree` · area: rendering

The compatibility `render_tree*` entrypoints now build a transient display list
and replay its commands, matching the retained production path. The parallel
recursive `WidgetNode` painter and its private traversal helpers were deleted,
so clipping, z-order, filters, controls, and effects have one authoritative
lowering path. This exposed and corrected a stale parity expectation: CSS
`filter` now emits the retained push/pop layer scope through either entrypoint.

The complete `mesh-core-render` library suite passes: 200 tests passed and 37
release-only benchmarks were ignored.

## 2026-08-02 — Stored frontend props are validated and ejectable

`working tree` · area: component settings

Frontend global and per-instance prop overrides now validate against the
primary component's canonical `<props>` declarations during startup, live
reload, embedded-component initialization, and `config doctor`. Unknown,
unexposed, wrong-typed, and constraint-violating values produce located
diagnostics and are removed from the runtime-facing namespace so the declared
default wins; the stored document remains untouched for repair.

`mesh-shell config eject <module-id>` now compiles the frontend declaration and
materializes effective exposed global props beside the effective surface
placement. Existing valid globals remain effective, declared defaults fill the
previously sparse block, instance overrides are preserved, and internal props
stay absent. The surface-config tests (28), focused shell prop tests (12 passed,
2 release-only benchmarks ignored), workspace checks, and an isolated real CLI
eject of `@mesh/navigation-bar` pass.

## 2026-08-02 — Settings renders the complete per-module graph

`working tree` · area: settings and module diagnostics

Installed-module rows in the advanced settings page now have an expandable
details control. The view reports required and optional interfaces with their
active providers, provided interfaces, module dependencies, required and
optional capabilities, icon/font/theme resources, native binary availability,
i18n catalogs, keybinds, and combined graph health and diagnostics. Empty
categories stay explicit rather than disappearing.

The settings frontend now accepts the canonical `interface=provider` strings
emitted by `mesh.debug.module_graph` as well as object-shaped values, fixing a
fixture-masked mismatch that could leave the active-provider section empty in
the running shell. The full frontend-compiler and module suites pass (63 + 158
tests; 20 + 3 release-only tests ignored), along with focused production graph
serialization and real settings-surface tests.

## 2026-08-02 — Core service calls join generic interface routing

`working tree` · area: module runtime and profiling

The audio contract now declares `play_sound(path)`. Startup sound dispatch
builds an ordinary capability-bearing `ServiceCommand` from `@mesh/shell`, so
contract validation, active-provider selection, method-call diagnostics, and
backend profiling all run through the same dispatcher used by module calls;
the shell no longer reaches into the `mesh.audio` handler map directly.

The backend-update benchmark also selects a running provider and matching
profiling sample by `(interface, provider)` rather than naming `mesh.audio`.
Its frontend cost is the largest rendered surface sample in the session, so
the scenario works for network, power, window-management, and future backend
interfaces without adding branches. Focused sound-routing, six backend
benchmark, and shipped-graph tests pass, along with `cargo check` for the shell.

The backlog item remains open for core-owned `mesh.debug`, `mesh.theme`, and
`mesh.locale` state paths that still need replaceable generic providers.

## 2026-08-02 — Frontend props generate settings controls

`working tree` · area: component settings

Installed frontend modules now project the exposed props of their primary
`.mesh` component into the module graph as a typed settings schema. The
settings frontend renders the resulting controls and reset actions, seeds them
from effective values, and sends typed set/unset requests. The shell restricts
those requests to `@mesh/settings`, validates names, types, and constraints
against the owning prop declarations, persists sparse profile-scoped global
overrides, reapplies live component settings, and requests a render.

The original backlog item is narrowed rather than closed: arbitrary
`settings_ui` components are recorded but are not mounted, and generated
controls do not yet target individual component instances.

The complete component, frontend-compiler, and module suites pass, as do the
focused shell tests for event authorization, typed requests, sparse override
updates, graph projection, and the real settings surface. The full shell suite
still has 23 unrelated existing failures (593 passed, 125 ignored), including
isolated option activation, navigation layout, and backend-debug assertions;
the same failures reproduce when run individually outside the changed paths.

## 2026-08-02 — External interface contracts reach runtime tooling

`working tree` · area: module contracts and LSP

Canonical manifest loading now resolves module-relative `contract.json` files
through the same validated package-loader path used by installed graph
construction. The LSP indexes the resulting `InterfaceContract` as the
authoritative interface shape and exposes exact Luau state types, method

obsolete `on_change` helper.

The complete `mesh-core-module` and `mesh-tools-lsp` test suites pass (158 + 83
unit tests, 6 LSP integration tests; 3 release-only module benchmarks ignored).

## 2026-08-01 — Typed embedded handler targets

`working tree` · area: component composition

`WidgetNode` event handlers and pre-bound handler calls now retain a typed
`HandlerTarget`: the local script handler is distinct from the optional embedded
component instance that owns it. Compiler namespacing, interaction lookup,
scheduled handlers, keybind subscribers, pressed-handler snapshots, and shell
dispatch pass that target without constructing or reparsing the former
`__mesh_embed__::instance::handler` encoding. Runtime-provided legacy strings
remain accepted at the compiler and test compatibility edges and are immediately
decoded into the typed representation.

This closes the remaining magic-string protocol at the component composition
boundary. Focused compiler, interaction, shell dispatch, `bind:this`, child-event,
and shipped navigation regressions pass; the complete shell test target also
compiles.

## 2026-08-01 — Typed component binding and popover channels

`working tree` · area: component composition

The compiler-to-shell boundary now carries public component values, per-prop
bindings, and `bind:this` in a typed `ComponentCompositionProps` record instead
of encoding binding metadata as `__mesh_binding_*` and `__mesh_bind_this`
attributes. Public prop projection no longer needs to identify and filter
reserved names, and component memo fingerprints include each typed channel.

Promoted-popover wrappers likewise carry a typed, copy-on-write authored-node
flag rather than `_mesh_promoted_popover`. The flag survives component memo
reuse and remains distinct from module-authored attributes. Embedded handler
targets still use the serialized `__mesh_embed__::` form and remain open in the
backlog.
