## 2026-08-02 — Keyed embedded component loops

`working tree` · area: component composition

`{#for item in items key={item.id}}` now evaluates the key in each iteration's
locals and carries that stable identity through component occurrence allocation
and memo lookup. Reordering a keyed list therefore retains embedded component
VM state and cached render results. Unkeyed loops deliberately retain their
existing positional identity, and retained native-widget reconciliation is
still the remaining backlog work.

**Verified.** Focused component-parser and shell composition regressions pass,
including a reorder that reuses both keyed component memo entries.

## 2026-08-02 — Keyed loop runtime reconciliation

`working tree` · area: component composition, interaction state

Keyed loop placement now flows into the retained tree's stable runtime node
keys as well as embedded-component instance keys. Native inputs, focus,
