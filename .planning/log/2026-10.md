## 2026-10-01 — Block review Priority 1: isolation and capability grants

`5dd71773`..`d5cb04fb` · area: scripting realm, module graph, capabilities, profiles

All six Priority 1 items from the
[2026-09-30 block review](../codebase/audits/2026-09-30-block-review/REPORT.md)
are fixed, one commit each, each with a regression test.

- **SH-01** (`5dd71773`). `commit_pending_profile_switch` now installs
  `ActivationPlan.effective_capabilities`, and `ActiveSnapshot` exposes them.
  Retained surfaces are re-prepared when a module present in both activations
  has a different grant. Running providers whose grant changed restart.
  Test: `committed_activation_replaces_the_previous_capability_grants`.
- **MOD-02** (`c897c9c8`). `TrustTier::for_source` no longer takes a module
  id: unsigned git is `community`, unsigned path is `local`. Unlocked modules
  under `@mesh/` stay `core` (`for_unlocked_module`), because install review
  and lock bookkeeping now reject git or path sources that claim the reserved
  scope (`check_installable_module_id`). Spec 01 §7 updated.
- **MOD-03** (`9c9d7749`). Every uninstall calls
  `RootModuleGraphManifest::forget_uninstalled_module`, which drops the
  module's approvals and `disabled` entry. The root is saved when that changes
  it, including for auto-discovered inventories. The forced path also saves
  now; before this it lost its reference cleanup when the inventory was
  implicit.
- **MOD-04** (`e803ade3`). An in-argument `*` matches only
  `[A-Za-z0-9._/@:+=-]`. `exec_argv_grant_error` rejects any wildcard for
  interpreters and launchers (`env`, `awk`, `python*`, …). For shells, the
  only wildcard it allows is a whole-argument `*` after an exact `-c` script.
  The Hyprland socket probe is now `sh -c 'test -S "$1" && echo ok' sh <path>`.
  Three test grants of `exec.argv:sh:*` became exact scripts. Spec 01 updated.
- **MOD-01** (`bcd6f2ff`). Provider priority no longer selects a contract.
  Identical inline copies share one declaration. Differing copies leave the
  interface undeclared and give every declarer a
  `conflicting_interface_declaration`. Interface modules still own their name.
  Spec 01 §4 updated. No shipped interface had more than one declarer.
- **RT-01** (`dbf8f068`, `d5cb04fb`). `getfenv`/`setfenv` are removed from
  realm globals before `sandbox(true)`. Template expressions are still
  closures inside the component chunk, so they keep the component's lexical
  locals. The host binds each closure's environment with
  `Function::set_environment` to a proxy that resolves call locals first and
  then records the member read.
  - The first attempt compiled each expression as its own chunk. That lost
    access to component locals and failed
    `template_expressions_use_component_lexical_scope_and_full_luau`, so it was
    replaced the same day.
  - Live `bind:this` function and table values are deep-wrapped by a Lua helper
    with an empty environment. Nested tables iterate through `__iter`;
    `pairs()` sees an empty proxy.
  - Frontend channel subscriber sets live in a locked metatable. Backend
    channels capture theirs in closures. `__subscribers` is no longer a field.
  - Test: `live_binding_values_cannot_reach_the_child_environment`.

## 2026-10-01 — Block review Priority 2: shell survival and bounded failure

`9518ebf7`..`03d263af` · area: effect scheduler, backend runtime, storage budget, run loop

- **SH-02** (`9518ebf7`). A failing effect no longer leaves `process_effects`
  with an error; that error used to stop the shell. It is recorded as a
  `shell_effect_failed` diagnostic for its source, and the function now
  returns the report directly. A core service call made inside the scheduler
  becomes a follow-up tagged with its call id and answers `queued`. The call
  is settled only when the request applies or fails. If the request started a
  durable control-plane or profile write, it is settled when that write's
  worker reports back. Durable writes that arrive while another is pending
  are parked by setting key: theme, mode, locale, icon theme, font, provider,
  enabled, prop. A later write to the same key supersedes the parked one and
  answers it. Parked writes re-enter the scheduler when the pending write
  completes. Effects that are dropped, discarded or purged answer their calls.
- **SH-03** (`9abea260`), scheduler half. `@mesh/shell` effects are deferred
  over budget but never counted toward quarantine. A source earns at most one
  violation per frame and loses one per frame within budget. Before this,
  every deferred effect counted, so one burst quarantined at once. Blocked
  causal chains are pruned with their transactions. Attribution of
  component-returned effects stays open in the backlog.
- **SH-12** (`d95fd0bd`). `retire_component` is the single removal path for
  profile replacement and frontend deactivation. It returns the unmount
  effects; profile replacement used to drop them. It purges the runtime's
  queued effects, call routes and popup grabs.
- **RT-03 / RT-05** (`11e607d8`). `PollFailed` became `CallbackFailed { stage }`.
  Stream callbacks share the poll rule: non-terminal until three consecutive
  failures. Backend events now use an awaited `send` on the bounded channel,
  so a full queue applies backpressure instead of ending the provider loop.
  The `Drop` path hands a terminal record to a task when the queue is full.
  The old test `bounded_event_sender_rejects_overflow_without_retaining_more_events`
  pinned the overflow-is-closed behavior and was replaced.
- **RT-02 / RT-10** (`db2b379e`). `recharge_storage(previous, next)` charges
  only growth against the aggregate budget. The per-document limit is still
  enforced by the storage manager. `ScriptContext` drop releases the
  side-effect budget of its queued events and element actions, and backend
  context drop drains its pending events.
- **SH-04** (`03d263af`). New flag `render_stalled`: a render pass that
  rendered a ready component and presented nothing. When it is set, ready
  render work waits for the next deadline, capped at 16 ms, instead of zero.
  The write-only `components_want_render` and `presented_last_frame` fields are
  deleted.
  - A first version keyed off any progress in the loop iteration. It broke
    `scheduler_wakes_for_visible_dirty_component_even_without_previous_present`,
    because a component dirtied after an idle iteration must still wake
    immediately. Narrowed the same day.
- `513b3f6d` removed an import that only test code used, which broke the
  scripting test build. Restored in `db2b379e`. Check with `--tests`.

**Validated.** Debug, `cargo test -p mesh-core-shell --lib` after each item,
compared by name against the Priority 1 baseline lists: no new failure names,
28 or 29 failures. `mesh-core-backend` passes 39 of 39. In
`mesh-core-scripting` the only failure is
`thread_vm_reclaims_dropped_context_environments`. Standalone it failed 1 of 3
runs, matching its flaky record.

## 2026-10-09 — Priority 3 second batch; Priority 2 closed

`e987fbba`..`ccec36a4` · area: theme tokens, interaction order, effect scheduler

- **RES-01 / RES-02** (`e987fbba`). User token overrides accept dotted,
  `--css` and dash names. An override that names an uninstalled module or holds
  a non-scalar value is skipped with a per-token diagnostic instead of failing
  theme composition. An exact `var()` alias now needs one fallback-free
  reference, so `var(--a) var(--b)` is no longer read as an alias, and nested
  fallbacks resolve recursively.
- **UI-06 / UI-07** (`f8960e70`). `paint_order_child_indices` and
  `children_in_paint_order` are the one child order for the display list and
  every pointer, focus and scroll walk. Before, a raised sibling drew on top
  while the one beneath it took the click. Tab order bands targets into rows in
  one pass over a total order, replacing a pairwise overlap comparator that
  was not transitive.
- **SH-03**, attribution half (`ccec36a4`). Shell-level request queues carry
  `SourcedRequest { request, origin }`. Every component callback attributes
  what it returns to that component's `EffectOrigin` (module id and runtime
  id): mount, unmount, retirement, tick, core events, service events, input,
  child-surface input, and the candidate mounts of a profile switch. Requests
  the shell builds itself have no origin and are charged by their target, as
  before. A request with an origin that is queued while an effect runs stays
  in that effect's transaction and depth, so cycle detection still sees the
  chain, but it is charged to its own component.
  - Before, a component flooding a request with no surface target, such as
    `PublishDiagnostics`, was charged to `@mesh/shell`. After the scheduler
    half, `@mesh/shell` is never quarantined, so the flood was deferred
    forever and shared core's budget. The test
    `component_tick_effects_are_charged_to_the_component` now quarantines that
    component after three over-budget frames.
  - Each component callback's output is now its own transaction instead of
    sharing one per loop iteration, so one component cannot use up the
    256-effect transaction budget for the others.

## 2026-10-10 — Block review UI-03 / UI-04 / UI-05

`d315b5d3` · area: keyframe animations, transitions

- **UI-04.** Lowered keyframe stops record the properties they declare
  (`KeyframeStop::properties`, from `TransitionProperties::of_property`). Each
  property interpolates between the nearest stops that declare it, with the
  base style as the implicit 0% and 100% keyframes. Before, every stop was a
  whole snapshot: an undeclared property passed through the base at that stop,
  and a rule without a 0% stop held its first stop.
- **UI-03.** Animation-only frames reuse the previous frame's computed style,
  which holds the last pass's animated values. The pass now keeps each animated
  node's authored values (`KeyframeBaseStyle`) and restores them before
  lowering and sampling. A node still showing what the last pass wrote counts
  as not restyled. Any other value counts as newly authored, so a restyle that
  lands exactly on the last animated value keeps the stored authored value.
  This fixes the drift and makes `fill-mode: none` restore the authored value.
- **UI-05.** Transitions are no longer removed for a node with any named
  animation. Keyframe-animated properties are taken out of the transition
  trigger, so keyframe output never starts a transition, and the keyframe pass
  writes over them. Other properties keep their transitions.
- The relayout bucket counts only properties a stop moves away from the base,
  so a constant declaration cannot force relayout.
- `transition-property` now also accepts longhands such as `padding-left`,
  through the same mapping.

## 2026-10-10 — Script tasks, typed `mesh.shell`, template directives

Uncommitted at time of writing · area: scripting host API, shell effects,
template parser, navigation-bar modules · plan: the
[direction note](../todos/pending/2026-10-10-runtime-architecture-direction.md)
(D2 scheduler, D3 for `mesh.shell`) and the
[authoring review](../todos/pending/2026-10-10-authoring-model.md).

- **Warm-up.** Per-hover and per-click logs (`mesh.events.publish`,
  `mesh.popover.activate`, popover promotion, xdg_popup destroy, tab-focus
  transfer, `set_surface_visibility`) moved from `info` to `debug`. The render
  resource worker now runs a completion waker after every job. The shell
  installs one that writes the loop eventfd, so pending icon, glyph and image
  jobs no longer hold the loop in 1 ms sleeps.
- **Tasks (D2 scheduler).** Each `ScriptContext` owns a deadline queue
  (`context/runtime/tasks.rs`). `task.delay(ms, fn)`, `task.spawn(fn, ...)`,
  `task.sleep(ms)` inside a spawned task, and `handle:cancel()` /
  `task.cancel(handle)`. Scheduling and cancelling never leave the context.
  `ShellComponent` takes its tick deadline from the runtimes. Due tasks run
  through `run_script_call`, the post-call path `call_handler_target` now
  shares, so they get the same budget, state sync, published events, neighbour
  resync and element actions. Limits: delay 0–24 h, 256 pending per instance,
  each enforced at the call. Tasks are dropped on `uninit`. A failing task is
  reported as a handler error, and the other due tasks still run.
- `shell.schedule-handler` / `shell.cancel-handler`, `ScheduledHandler` and the
  per-surface key map are gone. Publishing either channel raises an error that
  names `task.delay`. The six hover-bridge copies use `task.delay`. The theme
  and language popovers had shared a timer key with their triggers, which is
  how returning to the trigger cancelled the popover's own close. They now
  fire `CloseScheduled`, and the trigger calls `cancelPendingClose()` only
  while one is pending, because each `bind:this` call resyncs the neighbour
  (measured, see the performance log).
- **Typed `mesh.shell` (D3 for shell operations).**
  `context/runtime/shell_api.rs`: `show_surface`, `hide_surface`,
  `toggle_surface`, `hide_popover`, `activate_popover`, `set_surface_role`,
  `toggle_surface_role`, `promote_widget`, `demote_widget`, `set_widget_role`
  and `position_surface`. Each validates its arguments and the `shell.surface`
  grant at the call and queues a `FrontendEffect`. The shell lowers the queue
  through `typed_effects_to_requests_at`, with no channel match, JSON payload
  or registry re-authorization; the ABI adapter's scope check stays.
  `mesh.popover.*` and `mesh.locale.set` use the same queue. The surface and
  locale `shell.*` channels are removed from `OperationRegistry` and
  `script_event_to_request_at`. Publishing one raises an error naming its
  replacement, and the module scan reports `removed_shell_event_publish`.
  Debug channels are unchanged. Five call sites in settings,
  composition-editor and the nav-bar settings button migrated.
- **Template directives.** `class:name={cond}` and `style:prop={value}` are
  lowered by the parser (`parser/markup.rs`, `desugar_directives`) into the
  element's single `class` / `style` binding. Directives therefore reuse
  binding evaluation, dependency tracking and the retained diff. `{#if}` /
  `{:else if}` / `{:else}` and `{#for … key=}` already worked end to end and
  are now documented. The theme and language triggers use `class:` instead of
  a script-built `trigger_class`.
- Docs: `mesh-syntax.md` (shell requests, timers and tasks, directives,
  conditional and list blocks), spec 01 §4 and the promotable-surface table,
  and spec 11 §4.2.
- **Found:** `navigation_language_popover_closes_when_pointer_leaves_promoted_popup`
  fails at `7614977e` too. A promoted popup's own pointer-leave does not
  schedule its close in the harness. Added to the backlog.

## 2026-10-10 — First Wayland run of the new code; popup leave, layer sizing, RND-06/07

area: hover popovers, promoted popups, layer/window sizing, presentation,
test isolation · checked in a nested niri 25.11 (winit) driven through
`zwlr_virtual_pointer_v1`, with screenshots taken by `grim`.

**Live check (task 1 of the session).** The shell was hovered across the four
nav-bar popover triggers and into their popups. The settings surface was
opened, popped out into a window, docked back and closed, and its sidebar
clicked. The composition editor was opened and closed. Four defects showed up
that the test suite had not caught:

- **Popup pointer-leave (backlog item).** The shell loses it, not only the
  harness. Hover over a promoted popup was pruned on the next parent paint:
  `prune_stale_interaction_targets` judged the hovered node against the
  parent tree, where the promoted wrapper carries the `hidden` exclusion
  marker. The leave then had no path to fire on. `node_can_receive_target`
  now judges nodes under a promoted popover or window as their child surface
  sees them: the marker and the collapsed wrapper box no longer disqualify
  them, while `display`, `visibility`, `disabled`, `inert` and ancestors still
  do. `navigation_language_popover_closes_when_pointer_leaves_promoted_popup`
  passes.
- **Quick Settings never closed on leave.** Its `task.delay` callback called
  `hide_settings_selector` before that local was declared, so Luau resolved a
  nil global: `handler=task error=…attempt to call a nil value`. This was
  broken at `819fbbcb` too. It is now forward-declared. The trigger-leave test
  covers the settings button as well, renamed
  `navigation_hover_popovers_close_when_trigger_hover_leaves`; it fails on the
  old module. `navigation_hover_profile` now ends with 0 popovers open and
  asserts it.
- **Clicks missed on a narrowed layer.** niri configured the 920×900
  settings layer (700 of content plus the 200px tooltip reserve) at 920×799.
  The shell laid out and painted at the request, and the viewport scaled the
  buffer into the configure, while pointer coordinates arrived unscaled. So
  the pop-out button was unreachable. Three changes fix it.
  `render_components` applies a layer configure below the request on a fixed
  axis, and the tooltip reserve gives way first. Paint obeys a compositor-sized
  extent even after the surface has measured itself: the new
  `SurfaceExtent::bound_by_compositor` replaces the old fallback-only use of
  the extent, which also kept a popped-out window at its measured 920×700
  inside a 690×779 tile. The presentation input region keeps the content's
  height when the reserve shrinks. A root with a definite px size keeps
  requesting it, so `max-width: 100%` on settings fits a small output without
  latching the smaller size. Settings uses that, and fills its window
  (`:windowed`). Spec 01 states the layer rule.
- **RND-06.** `resolved_surface_size_for_config` used `max(configured, output)`
  for a spanning axis, which painted a margin-8 bar 16px past its configure.
  It now uses the output size only for an axis the configure left unset
  (`SurfaceEntry::configured_axes`). Before the fix, the nested bar ran past
  the right edge of the output.
- **RND-07.** Without a viewport, `surface_scale` now reports the integer
  `protocol_buffer_scale`, through `FractionalScale::render_factor`. Buffers
  are then always the logical size times the buffer scale, never a size that
  scale does not divide.

## 2026-10-10 — RES-03 / RES-04 / RES-14, RES-07 exec locale option

area: locale formatting, Luau locale and exec host APIs, nav-bar, quick
settings, audio popover and settings modules

- **RES-03.** `format_date` uses ICU4X `icu_datetime` 2.3 (the ICU crates
  moved 2.2 → 2.3 together) with Gregorian CLDR field sets, in the host's
  local zone through `libc::localtime_r` (`WallClock::local`). Styles:
  `short`, `medium`, `long`, `full` (with the weekday) and `month_day`. New
  `format_time` (`T::hm` / `T::hms`, in the locale's hour cycle) and
  `format_percent`. The `_at` variants take a `WallClock` for reproducible
  tests. Czech no longer gets Slovak month names, Slovak gets the genitive
  ("10. októbra 2026"), and Russian is no longer English. The hand-written
  month tables are gone. `format_percent` places the sign from a table of the
  CLDR percent patterns for the shipped locales; ICU4X's percent formatter is
  still in `icu_experimental`.
- **RES-04.** The clock uses `format_time` and `format_date(…, "month_day")`,
  with a translated tooltip (`nav.clock_full_date`). Every `%d%%` label
  (quick settings, nav-bar volume/brightness/battery, audio popover, settings
  audio and Wi-Fi pages) now uses `format_percent`. The audio popover declares
  and is approved for `locale.read`. Seen in niri: "23:40" / "10. 10." and
  "sobota 10. 10. 2026 o 23:40" under `sk`, battery "100 %".
- **RES-14.** `complete_fallback_chain` no longer appends `en`. English is a
  last resort after the module's `defaultLocale` in module lookups, bulk
  projection and core lookups. The published `chain` lists only the user's
  locales. Spec 07 §5 gains the step.

## 2026-10-11 — RND-09 final damage stage (RND-01, RND-08)

area: render damage, shell region paint, presentation SHM copy and protocol
damage

- `mesh_core_render::DeviceDamage` is the final stage. It converts logical
  rects with the `FractionalScale` cover rule, clips them to the buffer, splits
  them into disjoint rects, and collapses to the bounding box past 16
  (`MAX_DEVICE_DAMAGE_RECTS`, the protocol budget).
- **RND-01.** `paint_pixel_regions` clears and paints exactly the
  `DeviceDamage` rects. Before, each logical rect was rounded out on its own;
  at 1.5× two abutting rects overlapped by two device columns, the region-major
  replay painted the overlap twice, and a translucent root darkened there.
  `damage_that_overlaps_after_device_rounding_repaints_translucent_content_once`
  fails with the old conversion and passes now. (An opaque root hides the
  defect, because each replay repaints it; the test uses a translucent bar.)
- **RND-08.** `attach_shm_buffer` reports the disjoint union of the frame's

## 2026-10-11 — One hover-intent mechanism

area: scripting host API (`mesh.ui`), shell popover bridge, nav-bar triggers,
theme-selector, language-popover. This lands the design note
`todos/pending/2026-10-10-script-timers-and-typed-shell-ops.md` (deleted;
git keeps it) and the hover-intent part of D5.

- `mesh.ui.hover_intent(on_close, options?)` returns an intent with
  `enter` / `leave` / `cancel` / `pending`. It is written in Luau, compiled
  once per realm, and closed over the instance's own `task.delay`, so the timer
  keeps the instance's budget and lifetime. It took the shared-helper route
  rather than popover attributes: under the 00 §4 admission test the timer
  policy is behaviour the trigger composes, not something every `<popover>`
  owns.
- One delay: `mesh_core_elements::HOVER_INTENT_CLOSE_DELAY` (400 ms). The
  shell's surface-popover bridge (`POPOVER_HOVER_BRIDGE_DELAY`, 180 ms before)
  and the helper both use it.
- The four triggers (volume, theme, language, settings) own one intent each.
  The popovers forward enter and leave and run no timer of their own.
  `CloseScheduled`, `CloseRequested` from the bridge, `cancelPendingClose()`
  and the `popover_close_pending` cross-calls are gone; the ring re-centring
  that the popover's own close did now runs in `render()` when `open` turns
  false. Modules: 209 lines removed, 75 added.
- Docs: `mesh-syntax.md` § Hover intent. The `task.delay` example there no
  longer shows a hand-built close bridge.

**Validated.** Release. `mesh-core-scripting`:
`hover_intent_shares_one_close_timer_between_trigger_and_popup` and
`hover_intent_rescheduling_keeps_a_single_pending_close`. `mesh-core-shell
--lib`: 848 passed, 28 failed, all names in the `819fbbcb` baseline, including
the trigger-leave, promoted-popup-leave and language-option tests.
