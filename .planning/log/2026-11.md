## 2026-11-08 — Pointer hit tests prune subtrees by painted extent

The pointer traversals (`pointer_hit_test`, `pointer_press_hit`, `pointer_event_handler_hit`) visited every row of a fully built list. They now take an optional `PaintedExtents` oracle (`pointer_*_pruned`) and skip a child whose subtree painted nothing at the point. The oracle is the retained display list: `RetainedDisplayList::painted_subtree_bounds` is each node's `command_span.bounds`, which already includes ancestor transforms, effect overflow and clips, and `is_retained_scroll_owner` marks owners whose content bounds are unscrolled content space, so the traversal adds the live scroll offset of each such owner above a node before comparing. Rules that keep it sound: a node without a recorded extent (hidden, preclipped, new, never built) is never pruned; a scrolling node that does not replay its content disables pruning below it, because its build-time offset is baked into the bounds; bounds get a 1 px slack for the display list's integer rounding; and the component supplies the oracle only while nothing is pending (`dirty`, `style_only_dirty`, `animation_only_dirty`, `next_frame_only_dirty`, `dirty_types`, `frame_dirty`), since a pending change can move or add nodes the list has not seen. Wired into pointer motion, press, the press-target lookup, scroll, two-finger scroll and gesture capture. Tests: interaction unit tests (pruned equals full, a shrunk extent is skipped, unknown nodes are never pruned, retained-owner shift, non-retained scroller disables pruning) and `painted_extent_pruning_matches_the_full_hit_test_on_a_scrolled_uneven_list` (300 uneven rows, scrolled to the top, middle and end; hit, press and handler results equal the full traversal over a point grid; a hit visits 5–14 nodes). interaction 55, frontend-runtime 744, render 377 pass; `cold_icon_lookup_repaints_only_consumers_and_rejects_old_catalogs` fails with and without this change. Replay pruning for the same lists is still open in the backlog.

## 2026-11-08 — Uneven `{#for}` lists window against measured and estimated pitches

A long list whose items differ in size was built in full (a ~300 ms second frame at 2,000 rows). `VirtualRange` gained `spacers: Option<(lead, trail)>`; the compiler uses them in place of `skipped * (extent + gap)` when present. The host (`virtual_list.rs`) keeps a `PitchCache` per list: when the built items are not uniform, or a recorded extent no longer matches, the list enters variable mode (sticky until its length changes), records each built item's pitch (to the next item or trailing spacer, gap included), fixes an estimate for unbuilt items (mean of the known pitches when it enters), and chooses the window from cumulative pitches. ## 2026-11-08 — Performance candidates examined and not changed

- **Graph reads for user-initiated work** (`runtime/request.rs` provider selection and module enable, `backend/lifecycle.rs`): each runs after a durable write and owns a rollback; moving the ~215 ms read off-thread means threading continuations through rollback handling for rare actions. Left synchronous.
- **Popover target pooling:** target plus a 3-slot ring costs 1.2–1.4 ms (NVIDIA) and 3.2–5.6 ms (AMD) to allocate (`gpu_resize_allocation_workload`), and slots are created lazily one per frame, so pooling saves well under 2 ms per open. Not worth the lease complexity.
- **Persistent Skia shader cache:** `skia-safe` 0.97 does not bind `PersistentCache`.
- **Glyph/asset page growth re-upload:** pages are immutable snapshots so in-flight scenes keep their pixels; uploading only new cells would break that and needs a different ownership design.
- **Sparse-frame passes:** hover 0.52 ms p50, Appearance service frame 0.012 ms, so nothing to scope at those workloads.

`mesh.settings.set_prop` only accepts props declared by a module's entry component, so the preference props moved from `prefs-page.mesh` to `main.mesh`; the page reads stored values from `settings.namespaces["@mesh/settings"].props.global` and falls back to a `DEFAULTS` table that must match the declarations. Choice rows now render their options under the label instead of in a wrapping row that overlapped the next row. `@mesh/settings` also needed the nine new `service.*` grants in `config/module.json`.

## 2026-11-08 — Settings controls drive real services

New interfaces and Hyprland/systemd backends: `mesh.display` (`@mesh/hyprland-display`), `mesh.input` (`@mesh/hyprland-input`), `mesh.power-profile` (`@mesh/power-profiles-daemon`), `mesh.time` (`@mesh/timedatectl-time`), `mesh.bluetooth` (`@mesh/bluetoothctl-bluetooth`; the Bluetooth page had no provider before) and `mesh.idle` (`@mesh/hypridle-idle`, runs only when managed). Hyprland 0.56 uses a Lua config, so `hyprctl keyword` fails and changes go through `hyprctl eval "hl.config({…})"`/`hl.monitor({…})`; they are runtime-only and re-applied from `self.storage`. An interface is only loaded when a module in the active composition's closure uses it: `uses.optionalInterfaces` is not enough, so the six backends are `compose.backgroundServices` of every composition (without that the Settings module failed with `unknown capability 'service.display.read'`). Notification duration, popup count and history write the notification backend's props (new `max_popups`); units writes the weather `unit`; reduce motion, high contrast and reduce transparency write theme token overrides; clock 12/24 h, week start, battery percentage and low-battery threshold are read by `@mesh/glass-bar` from the `@mesh/settings` props. Rows with no possible effect (screen reader, sticky keys, thick focus ring, banner position, grouping, lock-screen content, privacy indicators, screen-share prompt, startup notifications, HDR on a missing provider) were removed. Verified only by unit tests and by probing `hyprctl`, `hyprsunset`, `powerprofilesctl`, `bluetoothctl` and `timedatectl` on the development machine; not exercised in a running shell.

## 2026-11-08 — Android-style detail pages

Settings pages gained a list → detail drill-down in `prefs-page.mesh` (`nav` rows set `detail`; every detail view starts with a Back action; row kinds `nav`, `text`, `secret`, `meter` were added). Wi-Fi (current connection, saved networks, available networks, VPN, hotspot, per-network details, join with password, forget, auto-connect), Bluetooth (adapter rename/discoverable/pairable, device battery/type/address/trust/forget/pair), About (model, firmware, OS, processor, memory and swap meters, graphics, storage with per-disk usage, network, displays, battery, runtime), Sound (output/input devices, per-application volume and mute, default device), Display (per-monitor resolution, refresh rate, scale, HDR) and Apps (app info) were rebuilt on it; the bespoke Wi-Fi, Bluetooth and Device components were deleted and the Audio page keeps its master volume above the device lists. New additive interfaces and providers: `mesh.network-details` (`@mesh/nmcli-network-details`), `mesh.hardware` (`@mesh/sysfs-hardware`), `mesh.audio-devices` (`@mesh/wpctl-audio-devices`); `mesh.bluetooth` and `mesh.display` were extended. The existing `mesh.network` and `mesh.device` contracts were left untouched because fixtures and benchmarks depend on them. Notifications can be muted per application (`muted_apps` on the notification daemon). The three new backends were run against captured output from the development machine; a `dependencies must precede use` bug was found the same way (a local helper defined after `dynamic_sections` made the view silently empty), so the render test now asserts at least one section. Not exercised in a running shell.

## 2026-11-08 — Preference pages restyled: one card per group, real Back header

The data-driven pages reused `settings-card` and `settings-control-row`, which both draw a border and background, so every row sat in a second bordered box. They now use their own `pref-group`/`pref-row` classes with divider boxes between rows (per-side border widths are not drawn by the renderer), tappable rows for navigation and actions, pill choice buttons, and a header with a Back button and the detail title in place of the old Back row. A page build that throws is caught and shown on the page instead of leaving it empty. Copy keys are only looked up where the catalog has them, so missing optional copy no longer fills diagnostics. Frames can be checked by painting `PixelBuffer` data in a test and converting it; embedded component handlers are addressed as `__mesh_embed__::<runtime key>::<handler>` and the highest `#n` is the live instance.
