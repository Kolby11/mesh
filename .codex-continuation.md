## Architectural decisions

- Durable settings revision is stored as top-level `revision`; legacy/missing
  documents start at zero.
- Durable profile revision is stored as `revision` in `ShellProfile`; zero is
  omitted when serializing legacy-compatible profiles.
- Locale writes are prepare → durable expected-revision commit → live runtime
  commit. Invalid catalogs, invalid locale tags, persistence failures, or stale
  revisions retain the current live snapshot.
- An active profile owns the locale override; without an active profile, the
  shared settings document owns it. Profile locale preparation also checks the
  shared settings revision so fallback changes cannot race the profile write.
- Module defaults participate only in catalog fallback resolution, never as
  component-local active-locale state.
